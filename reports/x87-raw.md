# Canonical raw x87 transfers and explicit update profiles

2026-09-06 14:21 UTC. Experimental v23 replaces five selectors: FLD m80, FSTP m80, FLD ST(i), FCHS and FCMOVNE. The fourteen authored sequences pass 688,144 cases across two explicit pointer/opcode update profiles. No game code was executed or newly accepted; P3 remains open.

Raw 80-bit values move as ten bytes, preserving signaling NaNs, denormals, pseudodenormals and unsupported encodings without entering floating arithmetic. Stack occupancy, masked indefinite values, suppressed unmasked results and later waiting faults use canonical State. Memory-first forms check pending faults before access and validate a stable ten-byte RAM span. A runtime metadata service receives the exact instruction PC, memory-operand flag and data-pointer-update flag; the fixture validates its CS/DS data without claiming general segment decoding.

The matrix varies every TOP and tag bitmap, sixteen payload classes, arithmetic flags including both conditional outcomes, exception masks/sticky states, operand alignment, compound sequences and waiting suffixes. Per-instruction hardware images distinguish newly recorded exceptions from later delivery. All 190,914 hardware fault cases match; eight extra native cases check pending faults before deliberately unsupported mappings, and eight diagnose those unsupported mappings. C0/C2/C3 are excluded because these instructions leave them undefined. Full remaining State, all raw payloads, memory, return/fault PC, host floating state, service counts and metadata are checked.

The first run retained 10,956 C1 differences. Hardware gave source underflow precedence when FLD ST(i) saw an empty source and an occupied destination slot. FCMOVNE preserved C1 during ordinary operations; empty operands still generated stack faults even when the condition was false. Those two fixes resolved the selected payload/state contracts. The earlier raw-v2 result still had 99,146 pointer-observation differences and is not presented as complete pointer agreement.

A separate 1,920-case hardware probe tests ten memory forms, using no Remill, SoftFloat or SEH capture. On this PC, FDP and FOP changed only when a tested instruction recorded an unmasked exception. The fixture initially assumed that observation required CPUID.7.0:EBX[6]=1, but the CPU reports EBX=0x239c27a9, with bit 6 clear and deprecated selector fields indicated. That failed guard remains preserved. A positive CPUID feature definition does not establish its inverse; the current calibration uses directly observed behavior. Intel also documents FOP compatibility-mode dependence. [Instruction semantics](https://cdrdv2-public.intel.com/812383/253666-sdm-vol-2a.pdf), [FCMOV condition/flags](https://cdrdv2-public.intel.com/671110/325383-sdm-vol-2abcd.pdf), [FOP compatibility mode](https://www.intel.com/content/dam/support/us/en/documents/processors/pentium4/sb/25366521.pdf), [CPUID feature definition](https://cdrdv2-public.intel.com/812218/architecture-instruction-set-extensions-programming-reference.pdf).

The experimental image-policy service now reserves bit 2 for data-pointer updates only on a newly unmasked exception, and bit 3 for the same opcode policy. Zero selects unconditional updates. Both policies are explicitly tested, with no AMD Jaguar execution claim and no automatic host-to-guest feature selection. The final raw-v5 matrix checks hardware FIP/FDP low bits and exact opcode bytes under the independently observed host rule; logical native pointers retain full width. Existing image flags at bits 0/1 and the upper 32-bit MXCSR mask retain their meanings.

The combined module also passes the 1,499,136 existing masked-stack and 557,864 image cases. The current numeric SoftFloat candidate remains separate. Before startup acceptance, older x87 producers must use the same metadata policy, FNINIT must reset segment metadata, and memory conversions/arithmetic, unmasked numeric results and MMX alias coherence must be completed. General guest memory and exception delivery remain open.
